核心結論

這份 FAL-LEG-MEPC-MSC.1/Circ.1《電子證書使用聯合指南》的核心，不只是允許船上用 PDF 取代紙本，而是建立一條完整的電子證書信任鏈：

旗國主管機關授權 → 合格電子格式 → 防竄改及電子簽章 → 唯一追蹤號碼 → 持續可用的驗證機制 → 船上 SMS 文件管制 → PSC 接受與查驗

其中任何一個環節失效，例如旗國未授權、證書版本過期、驗證網站無法使用、船上沒有驗證說明或船員不會操作，都可能使原本合法的電子證書在 PSC 現場產生合規風險。

一、文件主題與背景

1.1 文件基本資料

本文件將原本較偏向船舶電子證書的 FAL 指南，以及專門處理海員電子證書的 MSC 指南，整合成一份跨 FAL、LEG、MEPC、MSC 的聯合文件。

IMO 官方資料亦將本通函列為現行電子證書聯合指南，並說明電子證書若符合 IMO 指南、驗證網站要求且船上具備驗證說明，原則上應被視為與傳統紙本證書等效。(International Maritime Organization)

1.2 文件產生的原因

文件指出傳統紙本證書及早期電子證書使用上曾出現數種問題：

  1. PSC 或其他利害關係人質疑電子證書有效性。
  2. 船長與船員須額外聯絡公司、旗國或船級社說明。
  3. 紙本證書可能尚未送達船上。
  4. 紙本證書可能遺失、毀損或遭竄改。
  5. 海員證書種類多、更新頻繁，紙本管理負擔大。
  6. 不同旗國、RO、船級社的驗證方式不一致。
  7. 電子證書涉及伺服器、網路、電子簽章及個人資料，必須處理資安與隱私問題。

因此，本指南不是單純規定「可以電子化」，而是試圖建立各國及各組織都能辨認的最低共同特徵。

1.3 文件的法律定位

本文件屬於 IMO Circular／Guidelines（通函／指南），不是直接修改 SOLAS、MARPOL、STCW 或其他公約正文的修正案。

文件大量使用：

  • should：應當、建議採行；
  • are invited to：邀請會員國採行；
  • are urged to：敦促會員國採行。

因此，它的實際執行力主要來自：

  1. 旗國國內法及行政規則；
  2. 旗國對 RO／船級社的授權；
  3. IMO 公約中證書攜帶與查驗的要求；
  4. ISM Code 納入公司的安全管理制度；
  5. PSC 區域備忘錄及港口國主管機關的執行程序。

文件第 3 段也明確要求會員國在必要時建立適當國內法制，確保電子證書可以合法使用及接受。換言之，IMO 指南本身不是任何 PDF 都可被接受的通行證。

三、核心內容解析

3.1 適用範圍

指南適用於為證明符合 IMO 要求而簽發的各類電子證書，包括：

  • 船舶法定證書；
  • 船級相關電子證書；
  • 由旗國或其授權 RO 簽發的證書；
  • 海員適任證書及其他 STCW 相關電子證明；
  • 電子證書的列印版本。

但不適用於：

  • 船上出版品；
  • 操作手冊；
  • 指示文件；
  • 用來持續記錄船舶操作的 logbook／record book。

因此，電子油料紀錄簿、電子垃圾紀錄簿、電子壓載水紀錄簿等，不因本指南而自動合規，仍須適用其各自的公約、決議及旗國核准要求。

3.2 電子證書不等於掃描檔

指南所稱的 Electronic certificate（電子證書），必須是由主管機關建立或核准格式所簽發的正式電子資料，並能讓預定查驗者正常閱讀。

因此，下列文件不可直接視為合格電子證書：

  • 紙本證書掃描成的普通 PDF；
  • 手機拍攝的證書照片；
  • 沒有電子簽章的電子檔；
  • 可任意修改內容的 Word 或 PDF；
  • 未經旗國授權，由公司自行製作的證明；
  • 僅有船級社 Logo，但無法在線驗證的檔案。

真正的電子證書必須同時具備簽發權限、資料完整性、可驗證性及有效狀態。

3.3 五項最低必要特徵

第 4.1 節規定電子證書應符合以下五項要求：

1. 格式與內容正確

電子證書的格式、欄位及內容必須符合相關國際公約要求，包括：

  • 證書名稱；
  • 船名及 IMO Number；
  • 船籍港及旗國；
  • 總噸位、船型等適用資料；
  • 簽發日期；
  • 有效期限；
  • 年度、中期、定期檢驗的 endorsement；
  • 豁免、限制或附加條件。

電子化不可以改變公約原本要求的內容。

2. 防止未授權修改

證書必須受到保護，只有簽發者或主管機關授權人員才能：

  • 修改；
  • 更正；
  • 展期；
  • 加註 endorsement；
  • 重新簽發；
  • 撤銷或失效處理。

下載 PDF 後可以自行修改文字的文件，原則上不符合要求。

3. 具有唯一追蹤號碼

每份證書須有 Unique Tracking Number，UTN（唯一追蹤號碼），用以區別同一主管機關所簽發的不同電子證書。

UTN 的作用包括：

  • 查詢證書真偽；
  • 比對版本；
  • 確認是否撤銷；
  • 確認最新 endorsement；
  • 防止不同船舶或不同證書混用。

4. 明確顯示簽發來源

查驗者應能立即辨識：

  • 旗國主管機關；
  • 簽發 RO 或船級社；
  • 簽發人員；
  • 簽發權限；
  • 證書是否代表旗國簽發。

5. 包含電子簽章

證書必須有 Electronic signature（電子簽章），用於驗證簽發者及內容真實性。

必須注意，證書上顯示一張簽名圖片，不一定等於有效電子簽章。真正的電子簽章通常包含可由 PDF reader 或驗證平台查驗的密碼學資訊。

3.4 驗證網站與資安要求

若主管機關使用網站提供電子證書查閱或驗證，網站應具備：

  • Access control（存取控制）；
  • 防止未授權查詢或修改；
  • 防止詐欺及偽造；
  • 抵抗 cyberattack（網路攻擊）；
  • 系統備援；
  • 災害復原能力；
  • 持續服務能力。

文件腳註提及 ISO/IEC 27000 系列資訊安全管理標準，但這是示例，不代表所有系統只要取得 ISO 27001 證書即自動符合本指南。主管機關仍須核准整體簽發、儲存及驗證程序。

3.5 驗證的真正含義

指南所稱 Verification（驗證），不是只看文件表面，而是透過可靠、安全且持續可用的程序，確認：

  1. 證書確由合法簽發者簽發；
  2. 證書內容未被修改；
  3. 證書仍在有效期內；
  4. 證書尚未被撤銷或取代；
  5. endorsement 為最新狀態；
  6. 證書與該船、設備或海員相符。

因此，PSC 掃描 QR code 後看到網頁，並不代表驗證已完成；仍須比較網頁資料、電子檔及船舶實際資料是否一致。

3.6 船上必須具備驗證說明

第 5.1 節要求，船上應有電子證書的驗證說明，包括必要時確認週期性 endorsement 的方法。

最低限度應讓船長或負責船員知道：

  • 電子證書存放位置；
  • 如何開啟檔案；
  • 如何查看電子簽章；
  • UTN 在哪裡；
  • QR code 如何使用；
  • 驗證網站或應用程式；
  • 如何確認最新 endorsement；
  • 驗證失敗時聯絡誰；
  • 網路中斷時的替代措施。

「證書放在公司雲端，需要時再問岸上」通常不足以證明船上已具備有效控制。

3.7 海員電子證書的特別要求

海員電子證書涉及 STCW 適任資格及個人資料，因此有額外要求：

驗證可使用的方式

可包括：

  • 經核准的應用程式；
  • 核准的儲存資料；
  • UTN；
  • 海員識別號碼；
  • QR code；
  • 上述方式的組合；
  • 主管機關核准的其他方式。

船員持有的最低資料

若完整資料存放於遠端伺服器，海員仍須持有足以啟動驗證程序的最低資料，例如：

  • 姓名；
  • 證書號碼；
  • 海員識別號碼；
  • QR code；
  • UTN；
  • 主管機關指定的查詢資料。

原本證書的法律效果

只要海員持有真實且有效的電子證書，並符合相關條件，應視為已在船持有 original certificate（正本證書）。

這是本指南的重要突破：海員不再必然需要持有傳統紙本正本。

3.8 通知與 GISIS

決定使用電子證書的主管機關，應透過 GISIS Survey and Certification Module（全球整合航運資訊系統之檢驗與發證模組），提供：

  • 採用電子證書的資訊；
  • 電子證書類別；
  • 驗證網站；
  • 相關驗證資料。

IMO 官方說明，GISIS 可提供旗國電子證書資訊及真實性驗證連結。(International Maritime Organization)

但必須注意：

GISIS 主要證明某旗國或證書類別採用電子證書，不一定直接證明某一張個別證書目前有效。

個別證書狀態仍應透過旗國或簽發 RO 的驗證系統確認。

3.9 接受電子證書是「有條件接受」

第 7 節要求所有利害關係人，包括 PSCO，接受具備第 4 節特徵的電子證書。

因此 PSC 不應僅因以下理由拒絕證書：

  • 沒有濕簽；
  • 沒有浮水印紙；
  • 沒有鋼印；
  • 沒有紙本正本；
  • 證書僅以合格電子檔呈現。

但接受的前提是：

  • 旗國允許該證書電子化；
  • 電子證書具有必要特徵；
  • 能夠完成驗證；
  • 證書內容及日期正確；
  • 船上具有驗證說明。

IMO 2025 年 PSC 程序已明確把「有效證書」定義為可以由締約國或其 RO 以電子或紙本方式簽發，且日期、內容及船舶實際狀況均相符的證書。

3.10 納入 ISM Safety Management System

第 8.2 節要求船東、營運人及船員，依 ISM Code 第 11 節文件管制管理電子證書。

ISM Code 第 11 節的核心要求是：

  • 有效文件應存在於所有需要的位置；
  • 文件變更須經授權人員審查與核准；
  • 過期文件須迅速移除。

轉換成電子證書管理，就是：

ISM 要求 電子證書實務
有效文件可取得 船上須能立即開啟最新電子證書
變更經核准 endorsement、展期及更正須由授權簽發者完成
移除過期版本 舊證書、舊 endorsement 不得與最新版本混用
文件識別 應以證書號碼、UTN、版次及日期管理
船岸一致 公司系統與船上檔案須同步
人員熟悉 船員須知道如何展示及驗證

3.11 資安、反詐欺及營運持續性

第 9 節要求主管機關核准：

  • 簽發程序；
  • 儲存程序；
  • 驗證程序；
  • 資料交換程序；
  • 防止詐欺及資安事件的措施。

因此，電子證書系統的控制範圍不只 PDF 本身，也包括：

  • 帳號權限；
  • 簽章金鑰；
  • 憑證管理；
  • 伺服器；
  • API；
  • 電子郵件通知；
  • 下載連結；
  • 驗證網站；
  • 系統日誌；
  • 備份與災害復原；
  • 撤銷及重新簽發程序。

3.12 海員個資與儲存位置

海員電子證書的實體資料儲存位置應由主管機關決定。

指南建議主要資料存放於：

  • 主管機關控制的伺服器；或
  • 經主管機關核准的伺服器。

同時必須符合旗國個人資料與隱私法律。第三方，例如公司、代理、租家或 vetting company，可以在不違反隱私規定的前提下取得必要資料。

這表示驗證系統必須在兩個目標間取得平衡：

  • 讓 PSC、公司及其他合法查驗者容易驗證；
  • 避免海員個資對任何人無限制公開。

四、重要術語與定義

術語 中文解釋 實務重點
Administration 旗國主管機關 最終決定是否採用及接受電子證書

五、船級社與 RO 的實務影響

5.1 必須先區分「船級證書」與「法定證書」

船級社通常具有兩種不同身分：

船級身分

依船級規範執行：

  • 入級；
  • 船體及機械檢驗；
  • 船級符號；
  • 船級條件；
  • 船級證書。

RO 身分

受旗國授權執行：

  • SOLAS 證書；
  • MARPOL 證書；
  • Load Line 證書；
  • ISM／ISPS 證書；
  • BWM、AFS 等法定證書；
  • 法定 endorsement。

IACS 說明船級社的基本角色是制定及執行船舶設計、建造、維護及檢驗的技術要求；Tokyo MOU 則將 RO 定義為代表旗國執行法定檢驗並簽發或簽註法定證書的組織。(Safer and Cleaner Shipping - IACS)

因此：

同一份電子系統可以同時管理船級與法定證書，但兩者的法律來源、簽發權限及 PSC 後果不同。

5.2 旗國授權矩陣必須明確

船級社不能因自身已有電子證書平台，就自動對所有旗國及所有證書簽發電子版本。

應建立：

旗國 × 證書類別 × 證書狀態 × 簽發權限

例如：

檢查項目 可能差異
旗國是否接受 e-cert 不同旗國政策可能不同
可電子化證書類別 部分旗國可能只授權特定證書
Interim certificate 可能有不同程序
Short-term certificate 可能受旗國個別限制
Extension 通常須特別旗國核准
Manual endorsement 是否允許船上或驗船師離線簽註
海員證書 通常由旗國本人系統管理，不一定由船級社簽發

ABS 的電子證書操作說明也把確認旗國是否接受電子證書列為實施的第一步。(Eagle)

5.3 船級社電子證書平台的最低要求

RO／船級社的平台至少應具備：

  1. UTN 或同等唯一識別碼；
  2. 數位簽章；
  3. 防竄改 PDF；
  4. 公開或可合理取得的驗證介面；
  5. 即時有效狀態；
  6. endorsement history；
  7. 撤銷及取代狀態；
  8. 船名、IMO Number、證書號碼交叉查詢；
  9. 系統可用性監控；
  10. 備援及災害復原；
  11. 稽核紀錄；
  12. 24 小時緊急支援聯絡方式。

DNV、LR、ABS 及 ClassNK 的現行平台均採用 UTN、數位簽章、線上資料庫、QR code 或船舶識別資料等方式提供第三方驗證。(DNV)

5.4 驗船師簽發程序會受到影響

完成檢驗後，驗船師或簽發單位不能只將證書上傳到公司系統就結案，還應確認：

  • 證書已正式簽發；
  • 電子簽章有效；
  • UTN 已生成；
  • 有效日期正確；
  • endorsement 正確；
  • 驗證平台已同步；
  • 舊版本已作廢；
  • 船方已收到或可取得最新版本；
  • 臨時或短期證書狀態清楚；
  • 需要時已附旗國授權或 declaration letter。

尤其在年度或中期檢驗完成後，若平台已更新但船上仍保留舊 PDF，會造成「平台資料與船上文件不一致」。

5.5 RO 的責任風險

電子化不會減少 RO 對法定證書的責任。

可能涉及 RO 責任的情況包括：

  • 未經旗國授權簽發電子法定證書；
  • 錯誤延長證書有效期；
  • endorsement 日期錯誤；
  • 船舶資料錯置；
  • 已撤銷證書仍顯示有效；
  • 系統中存在兩份互相衝突的有效版本；
  • 簽發或展期違反公約限制；
  • 應由 RO 完成的證書控制發生重大錯誤。

Tokyo MOU 的 RO 責任判定原則特別涵蓋由 RO 簽發或簽註的法定證書，以及違反公約限制而不當簽發或延長證書的情況；但實際歸責仍須依個案、最後檢驗者及缺失性質判定。

5.6 船級／ISM 稽核重點

在 ISM 稽核中，電子證書通常會被視為文件及資料管制的一部分。稽核時可能查看：

  • 公司是否有電子證書程序；
  • 誰負責下載及更新；
  • 船岸資料是否一致；
  • 是否定期檢查到期日；
  • 舊版本是否移除；
  • 船員是否接受 familiarization；
  • 驗證平台中斷時的應變；
  • 電子檔是否定期備份；
  • 電子郵件或 portal access 變更是否受控；
  • 是否定期抽查電子簽章及 UTN；
  • 是否有網路釣魚、假 QR code 或假證書通報程序。

六、PSC 實務影響

6.1 電子證書會成為 PSC 初始查驗的一部分

Paris MoU 說明，PSC 登輪通常首先檢查船上證書及文件，並依船況、設備及船員整體情形決定是否進行更詳細檢查。(parismou.org)

電子證書下，PSCO 的基本查驗流程大致如下：

步驟一：確認證書是否應在船

PSCO 先確認：

  • 船型；
  • 總噸位；
  • 航區；
  • 旗國；
  • 適用公約；
  • 應持有的證書種類。

步驟二：確認簽發權限

檢查：

  • 旗國是否採用電子證書；
  • 簽發者是否為旗國或其 RO；
  • 該 RO 是否獲授權簽發該類證書；
  • GISIS 或旗國公告是否有相關資料。

步驟三：檢查電子檔表面資訊

包括：

  • 船名；
  • IMO Number；
  • Official Number；
  • 證書號碼；
  • 簽發日期；
  • 到期日；
  • endorsement；
  • 電子簽章；
  • UTN；
  • QR code；
  • 簽發來源。

步驟四：執行線上或電子驗證

依船上說明：

  • 掃描 QR code；
  • 輸入 UTN；
  • 輸入 IMO Number；
  • 檢查 PDF 電子簽章；
  • 比對平台資料；
  • 確認證書未被撤銷或取代。

步驟五：比對船舶實況

即使電子證書真實，PSCO 仍會確認：

  • 船況是否與證書相符；
  • 設備是否存在且可用；
  • 船員人數及資格是否符合；
  • endorsement 是否反映最新檢驗；
  • 限制條件是否遵守。

6.2 PSC 不應只因「沒有紙本」開缺失

只要證書：

  • 符合本指南；
  • 由合法主管機關或 RO 簽發；
  • 可完成驗證；
  • 船上有驗證說明；
  • 日期及內容有效；

PSCO 原則上應接受。

IMO《2025 年 PSC 程序》明確承認有效證書可以電子或紙本方式簽發。

因此，下列情況本身不應構成缺失：

  • 沒有紙本正本；
  • 船長只能在電腦或平板展示正式電子證書；
  • 電子證書沒有手寫簽名；
  • 電子檔以數位簽章取代鋼印。

6.3 可能引起 PSC 缺失的情況

高風險情況

問題 PSC 可能關注
電子證書已過期 無有效證書
平台顯示 revoked／invalid 證書無效或遭撤銷
IMO Number 不符 證書可能錯船或偽造
endorsement 未更新 定期檢驗狀態不明
旗國未授權該類 e-cert 簽發形式可能不被接受

QR code 指向可疑網站 詐欺或網路安全風險

Tokyo MOU 於 2025 年年報中特別提及偽造船籍及證書案件增加，並同意研議更有效的處理措施，顯示未來 PSCO 對電子證書真實性查驗很可能更加重視。

6.4 驗證失敗不一定立即等於扣船

應區分三種情況：

情況一：技術性暫時問題

例如：

  • 港內網路不良；
  • 驗證網站短暫維護；
  • QR code reader 無法使用。

若船上仍有：

  • 有效數位簽章的電子檔；
  • UTN；
  • 旗國／RO 聯絡方式；
  • 其他驗證入口；
  • 足夠證據證明證書有效；

通常應先採取替代驗證。

情況二：文件管制缺失

例如：

  • 船上保留舊版本；
  • 最新 endorsement 未下載；
  • 船員不熟悉程序；
  • 驗證說明缺漏。

這可能形成文件或 ISM 相關 deficiency，但不一定單獨達到 detention 程度。

情況三：無有效證書或證書明顯無效

例如：

  • 過期；
  • 撤銷；
  • 偽造；
  • 錯船；
  • 未經授權簽發；
  • 不當展期；
  • 關鍵法定證書完全無法證明有效。

IMO PSC 程序指出，若船舶沒有有效證書，或證書與船舶實況不符，可形成進一步詳細檢查的依據；缺少公約要求的有效證書亦可能支持 detention，但最終仍取決於證書種類、缺失嚴重度及港口國判斷。(wwwcdn.imo.org)

6.5 電子證書有效，不代表船舶不會被深入檢查

有效證書只證明證書本身符合形式及有效性要求。

若 PSCO 發現：

  • 消防設備失效；
  • 救生設備與 Record of Equipment 不符；
  • 船員不熟悉操作；
  • 船體或機械狀況明顯不良；
  • 污染防制設備無法正常運作；
  • 證書內容與船況不符；

仍可形成 clear grounds（明確理由），進行更詳細檢查。

因此電子證書不是對船況的絕對保證，也不限制 PSC 對實際合規狀態的查驗。(wwwcdn.imo.org)

七、船上建議準備的「電子證書 PSC 套件」

船上至少應保持下列資料：

項目 建議內容
正式電子證書 原始簽發 PDF，不是截圖
最新 endorsement 確認年度／中期檢驗已更新
UTN 清單 可快速對應各證書
驗證說明 最好有英文版
QR／驗證入口 定期測試是否有效
旗國授權資料 Marine Notice、Circular 或 Declaration Letter
RO 聯絡方式 24 小時緊急聯絡資訊
離線備份 船上電腦及獨立儲存媒體
紙本參考件 可供快速查閱，但不取代正式電子檔
SMS 程序 包含更新、備份、過期移除及驗證失敗處理

證書到期表 同時管理到期日及 endorsement due date

八、建議的船上 PSC 操作流程

登輪前

  1. 檢查所有法定證書到期日。
  2. 確認年度／中期 endorsement 已完成。
  3. 抽查每份證書 UTN。
  4. 測試 QR code 及驗證網站。
  5. 確認船上與公司版本一致。
  6. 移除過期或被取代版本。
  7. 準備旗國及 RO 電子證書說明。
  8. 指定一名船員負責操作。

PSCO 要求證書時

  1. 先提供證書清單。
  2. 在船上電腦開啟正式 PDF。
  3. 顯示電子簽章、UTN 及 endorsement。
  4. 依驗證說明開啟官方網站。
  5. 比對網站與證書資料。
  6. 必要時提供紙本列印件方便閱讀。
  7. 不要只提供手機照片、電子郵件截圖或不明網路連結。

驗證網站無法使用時

  1. 保留錯誤畫面或時間紀錄。
  2. 改用另一網路或裝置。
  3. 檢查 PDF 數位簽章。
  4. 使用替代驗證入口。
  5. 聯絡公司 DPA、旗國或 RO。
  6. 提供旗國 Marine Notice 或 RO declaration。
  7. 記錄採取的處理措施。

九、易混淆或需注意之處

9.1 電子證書與掃描紙本不同

掃描紙本通常只能證明有人曾持有某張紙，不能證明：

  • 現在仍有效；
  • 未被撤銷；
  • 未被修改；
  • 是最新版本。

9.2 電子簽章與簽名圖片不同

簽名圖片容易複製貼上。

有效電子簽章應能：

  • 驗證簽發者；
  • 顯示簽章有效狀態；
  • 偵測文件簽章後是否被修改。

9.3 QR code 不是證書本身

QR code 只是驗證入口。即使 QR code 可開啟網頁，也須確認：

  • 網域是否為官方；
  • HTTPS 憑證是否正常；
  • 網頁資料是否與證書一致；
  • 證書狀態是否有效。

9.4 列印版不宜單獨當作電子正本

列印件可供快速查閱，但紙張本身通常不能保留完整數位簽章資訊。

除非旗國另有明確規定，船上最好同時保存：

  • 原始電子檔；
  • 可驗證 UTN；
  • 驗證說明。

ABS 現行說明也指出，正式有效者是電子形式的證書，紙本列印件主要作為參考。(Eagle)

9.5 GISIS 不是個別證書資料庫的完全替代品

GISIS 可確認旗國電子證書政策及相關驗證入口，但個別證書是否：

  • 有效；
  • 續期；
  • 撤銷；
  • 被新版本取代；

仍須查詢實際簽發系統。

9.6 船級社有電子系統，不等於旗國已授權

必須分別確認：

  • 船級證書可否電子化；
  • 法定證書是否有旗國授權；
  • 該證書類別是否包含在授權範圍；
  • endorsement、展期及臨時證書是否另有規定。

9.7 「持續可驗證」不代表只依賴單一網站

若唯一驗證網站故障，且沒有：

  • 備援站；
  • 數位簽章；
  • 聯絡查證；
  • 離線驗證；
  • 災害復原；

便可能不符合可靠及持續可用的概念。

十、總結與複習重點

  1. 本指南整合船舶電子證書與海員電子證書要求。
  2. 電子證書不是普通 PDF 或紙本掃描檔。
  3. 合格電子證書至少要有： 正確格式、防竄改、UTN、明確簽發來源及電子簽章。
  4. PSC 應接受符合條件的電子證書，不應僅因缺少紙本而拒絕。
  5. 接受不是無條件，仍須確認旗國授權、證書有效及可驗證。
  6. 電子證書必須納入 ISM Code 第 11 節文件管制。
  7. 船級社作為 RO 時，須依旗國授權簽發法定電子證書。
  8. 驗證平台必須具備資安、備援、防詐欺及持續服務能力。
  9. 船上應保存正式電子檔、驗證說明、UTN、最新 endorsement 及備援資料。
  10. 電子證書有效並不妨礙 PSC 因船況或操作缺失進行更詳細檢查。
